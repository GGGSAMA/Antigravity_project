# 恩仇因果系统与核心循环 (Karma & Social Core Loop)

本设计文档奠定了游戏最核心的驱动力：**拒绝无脑刷怪，打造一个充满人情世故、资源极度匮乏、恩怨交织的真实修仙社会。**

## 核心设计哲学
修仙本质上是“逆天行事”，更是“与人斗”。
玩家的终极动力不是简单的“把攻击力升到 999”，而是活生生的情感诉求：**装逼打脸、报答当年一饭之恩、冲冠一怒为红颜、寻觅倾国倾城的道侣**。

## 1. 核心循环：因果驱动的成长螺旋
游戏的底层驱动循环不应该是“打怪->掉装备->打更强的怪”，而应该是：
`争夺稀缺资源` -> `结缘/结仇` -> `遭遇打压/危机` -> `隐忍苦修提升` -> `报恩/复仇（装逼）` -> `接触更高阶层，引发新恩怨`

### 1.1 资源的高度稀缺性
正如“凡人流”小说（如韩立）的设定，修炼极度困难。
- **天然壁垒**：高灵气地块（如刚才实现的雪山灵脉）天然被大宗门和高阶妖兽霸占。
- **修为压制**：去新的地图或跨越高阶境界时，系统要有意“卡”玩家，甚至出现重伤跌落境界的剧情，强行制造困难，让每一次实力的恢复和提升都伴随巨大的成就感。

## 2. 两条截然不同的修仙道路

### A. 正道苦修流（韩立式）
- **特点**：资质平平，稳扎稳打。
- **玩法**：在夹缝中生存，低调采集灵草，结交善缘。偶尔捡漏，被大佬追杀时只能隐忍逃入穷乡僻壤（如毒瘴沼泽）苦修。
- **情感反馈**：大器晚成。百年之后神功大成，出山一巴掌拍死当年欺负自己的仇家，震撼整个修仙界。

### B. 邪修劫掠流（极道式）
- **特点**：走捷径，杀人夺宝。
- **玩法**：因为资质太差或者等不及，直接在野外截杀其他 NPC，抢夺资源。甚至布置魔阵，吸干一块领地的灵气（导致 `corruption_level` 上升）。
- **情感反馈**：爽快但极其危险。杀人越货会导致极高的“仇恨值（业力）”，满世界都会是追杀你的正派人士或寻仇的亲友团。为了活命，必须被迫以战养战，疯狂提升修为。

## 3. 《鬼谷八荒》式人际社交网络底层算法 (Tale of Immortal Style Mechanics)
NPC 不再是站桩发任务的工具人，而是处于一张庞大、敏感的“有向图”关系网中。为了实现类似《鬼谷八荒》中“打了小的来老的”那种极致的人际动态，我们采用**“双轴数值 + 拓扑图谱”**的设计：

### 3.1 关系图谱与双轴数值 (Dual-Axis Relationship Object)
每个 NPC 维护一个社交字典（以对方 ID 为 Key）。字典内包含：
- **身份羁绊 (Identity Tags)**：父母/子女、道侣、师徒、义结金兰等。这些是硬性连接，提供极高的固定加权。
- **亲密度 (Intimacy, 0~100)**：决定正面交互的权重（主动送礼、危难施救、传授功法）。
- **仇恨度 (Hatred, 0~100)**：决定负面交互的权重（千里追杀、暗中下毒、造谣中伤）。
> **注**：亲密与仇恨双轴独立存在，允许出现“相爱相杀”或“因爱生恨”的复杂局面。

### 3.2 告别“全知上帝”：线索与延迟仇恨的连锁传递 (Evidence-Based Chain Reaction)
绝对不能像某些游戏那样“在荒郊野岭杀个人，十万里外的师傅瞬间知道凶手”。我们的系统遵循严格的**信息时空延迟**原则。
当极端事件发生（如：玩家在毒瘴林击杀了 NPC B）时，并不会触发全局即时广播，而是生成一个**【命案线索/因果源】**：
1. **死讯知晓 (Life Slip) 与 凶手未知**：B 的师傅 C 留在宗门的“本命玉牌”碎裂，C 瞬间只知道 B 死了（状态变为“悲痛”），但**绝对不知道凶手是谁**。
2. **Chunk 范围与概率暴露 (Chunk-Based Probability)**：
   为兼顾性能（LOD）与真实感，系统不采用死板的“物理追踪单个目击者”，而是采用**基于区块（Chunk）的概率模型**：
   - 每个城市/宗门/野外区域都有一个属于自己的 `范围标识(Chunk)` 和 `人口密度系数`。
   - **人口系数决定暴露率**：在人多眼杂的坊市杀人，暴露的概率极高；在渺无人烟的毒瘴林杀人，基础传播概率理论上接近于 0。
   - **时间 × 概率 的发酵**：随着时间推移，系统会在后台不断掷骰子（`当前区域人口系数 × 时间发酵常数`）。只要时间够长，恶名总有概率慢慢传到仇家的耳朵里。
   - **保底反侦察（绝对查不到是不可能的）**：即便在 0 人的绝地杀人，如果死者身上有【临死反扑/血咒】或者其师傅精通【天机推演】，系统会赋予一个强制的发现概率，确保高端局不会存在绝对完美的犯罪。
3. **仇恨传递公式**（在确认凶手后结算）：`新增仇恨值 = 事件基础仇恨(杀人=100) × 亲密度加权 × 性格护短乘区`。

### 3.3 社交欲望如何接入“收益打分”模型 (Social Utility Integration)
人际关系必须与我们在 `npc_behavior_ai_design.md` 中设定的“打分系统”无缝对接：
- **复仇/寻凶欲望 ($N_{revenge}$)**：如果已知凶手，【追杀】得分极高；如果未知凶手，【前往出事地点调查】的得分登顶。
- **实力威慑 (Power Deterrence)**：如果师傅 C 是筑基期，而仇人玩家已经突破到了元婴期。由于战力校验相差太大，【追杀】行为的得分会被大幅削减。C 只能被迫选择【隐忍苦修】或【到处造谣毁坏玩家名声】。
- **报恩/社交欲望 ($N_{social}$)**：亲密度高时，如果对方（如玩家）恰好缺乏某样材料，NPC 自身的【赠予物品】行为会获得极高加分，主动跑来找玩家送礼。

### 3.4 记忆网络与区块流言的扩散 (Chunk Gossip Propagation)
在 LOD 调度下，情报的传播不强求 100% 物理真实，而是采用更高效的降维算法：
- 哪怕 NPC 处于“背景池（休眠）”，仇恨字典也是持久化的。
- **流言的区块扩散**：当一个 Chunk 的凶案被暴露后，它会像波纹一样，以一定的概率向相邻的 Chunk 传染。你在无人角落干的坏事，起初恶名只在事发地周围的局部区块流传，经过长时间（数月/数年）的概率累加计算，才会彻底传遍整个修仙界中心。

## 4. Godot 组件化架构落实 (Attachable Component Node Design)
基于上述理论讨论，整套“恩怨因果与流言传播”系统在 Godot 中的工程实现，**绝对不会**硬编码在 NPC 的主脚本里，而是采用高度解耦的**“可挂载节点组件（Component Nodes）”**设计模式：

- **`KarmaTrackerComponent` (因果记忆组件)**：
  可以自由挂载到任何实体（玩家、NPC 甚至守山大妖）身上。专职负责维护上述提到的“亲密/仇恨双轴字典”，并对外暴露 `add_hatred()` 或 `modify_intimacy()` 接口。
- **`GossipEmitterComponent` (定向因果源组件)**：
  **核心优化点：流言绝不进行无差别的 AOE 广播**。无关的 NPC 计算流言毫无意义且浪费性能。该组件挂载在案发现场，当 Chunk 抛出“概率暴露”判定成功时，它会**精准读取死者的“社交字典”**，提取出“利益相关者（如死者的亲友、仇人）”名单。情报只会定向推送给这群特定的人。
- **`GossipReceiverComponent` (情报接收组件)**：
  挂载在利益相关者身上。接收到定向推送的命案情报后，触发 `KarmaTracker` 的更新，从而将其打分系统导向【复仇】或【调查】行为。

这种“即插即用 + 精准定向”的设计，意味着系统过滤掉了 99% 毫无意义的路人计算。哪怕你以后加一条“通灵的看门狗”，只要给它挂上这些 Node 并在字典里，它立刻就能融入关系网，且绝不会污染核心的 AI 性能。
